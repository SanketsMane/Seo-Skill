# /seox plan <business-type or url> — SEO strategy

If given a URL, run a quick audit first (`audit.md` with `--quick`) so the plan starts from reality. If given only a business type, ask (once, compactly) for: offering, audience, markets/languages, competitors, current site status, goals, resources (dev/content capacity).

## Deliver
1. **Goals** — business outcomes → SEO KPIs (qualified organic sessions, conversions, visibility on priority topics). No invented baselines.
2. **Audience & search intent** — personas, jobs-to-be-done, intent mix.
3. **Keyword clusters** — from `keywords.md` method; label volume "not measured" unless a data tool is connected.
4. **Topic clusters / pillar & supporting pages** — table: pillar · supporting pages · intent · page type · priority.
5. **Site architecture & internal-link model** — URL structure, hubs, breadcrumbs, how supporting pages link up/across.
6. **Technical roadmap** — from audit findings, ordered by impact × effort.
7. **Content roadmap** — what to create, update, consolidate, prune.
8. **GEO roadmap** — entity clarity, answer blocks, original data assets, crawler policy decision.
9. **Authority strategy** — earned links/mentions through genuinely linkable assets (original research, tools, expert commentary, partnerships, digital PR). No link schemes.
10. **Measurement** — Search Console, analytics, CWV, rank tracking if available; reporting cadence.
11. **30 / 60 / 90-day plan** — concrete tasks with owner type (dev/content/marketing) and dependency order. Fixes that block indexing come first.

Keep it decision-ready: every item has a reason tied to evidence or a stated assumption.
